Decisions and deviations:
- **`subscribeLimit` and the 429 message live in `src/lib/rate-limit.ts`, not beside the action.** `src/app/actions/lead.ts` carries `'use server'` and such a module may export only async functions — the S14 bug documented in `lead-state.ts`, which surfaces at request time and not at build time. The API route and the action import the same gate, which is also what makes them share one bucket.
- **The magic link still answers 200 when limited.** §14.2.1 says "everything answers 429"; this one route is the exception, and it is O2's decision reaffirmed rather than a new one. A 429 tells a prober which addresses are being counted, which is exactly the account-existence oracle the neutral answer exists to close. The limiter stops the mail, not the answer; the refusal is in the log. `tests/abuse.mjs` asserts the 200s as the correct result and says why.
- **The public CSP has nowhere to report to.** §14.2.4's "flip it to enforcing after a week of clean reports" is not achievable as written: the policy carries no `report-uri`/`report-to`, so reports reach each visitor's browser console and nothing else, and `src/app/api/csp-report/` is outside this phase's owned paths. Flagged loudly in `KNOWN-ISSUES.md` and in the runbook's own flip instructions rather than shipped as a collector nobody watches.
- `script-src` keeps `'unsafe-inline'`/`'unsafe-eval'`: Next's App Router ships an inline bootstrap and inline flight data on every page, and the alternative is a per-request nonce, which makes every page dynamic — the opposite of what O19 is about. Named in `next.config.ts` and the runbook as O19's to revisit.
- The header `source` patterns were verified against a real `next start`, not assumed: `headers()` matches the PUBLIC path, so `/members` gets the private policy before the middleware rewrites it into `/sites/guide/members`. The first attempt — a named param with a negative lookahead — silently matched everything; the unnamed `'/((?!admin$|admin/|members$|members/).*)'` is what actually excludes the private tree, which is why `/admin` carries exactly one CSP.
- `tests/abuse.mjs` sends the brand in `x-forwarded-host`, not `Host`: `fetch` refuses to set `Host` (forbidden header name), and the middleware reads `x-forwarded-host` first anyway because that is what Hostinger's proxy sets. Same reason the runbook's health section spells out what happens if a host ever fails to set `x-forwarded-for`.

Pre-handoff audit (§4.9): `npm run verify` re-run green (437 tests); `node tests/abuse.mjs` re-run green against a fresh `next start`. The adversarial re-read of the diff found one fragility and two accepted costs. The fragility: `loginAction` was clearing its counters with `reset('adminLogin:' + key)`, rebuilding by hand the namespace `takeLimit` applies — the day that naming changes it silently stops resetting and the symptom is an admin locked out for fifteen minutes after typing the right password. Now `resetLimit(name, key)`, with a test that asserts the namespace. The two accepted costs are in `KNOWN-ISSUES.md`: a shared IP (an office, a CGNAT mobile carrier) shares a bucket, which is the one limit whose false positive costs a lead; and anyone who knows Anton's admin address can hold the login shut by keeping that email's bucket full — deliberate, because the alternative is unlimited bcrypt guesses at one account from a botnet.

Where O19 looks first: `src/lib/rate-limit.ts` (`LIMITS` is the whole policy; add a row rather than a number in a route), `docs/runbook.md` for what `/api/health` means, and the `PUBLIC_CSP` comment in `next.config.ts` before touching rendering — the nonce question and the per-request `<html lang>` problem in `docs/improvement-report.md` §1.11 are the same problem. `src/proxy.ts` now strips `x-site`, so anything that moves brand resolution earlier must keep that strip.
